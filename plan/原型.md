## 原型  
portunex-server（Rust 网关）做的是转发和路由——粘性会话、负载感知、P2C 选择；isthmus 做的不是转发，是真实驱动本地 Claude Code CLI 并把 agent loop 伪装成无状态 API。你的请求最终落到某个容器里一个长期活着的 subagent slot 上。

  
  
最终配置模型


| 配置               | 默认值               | 出站 system 结构                                    |
| ---------------- | ----------------- | ----------------------------------------------- |
| `system_layout`  | `zero`            | billing 内含 `prompt_version=官方句`，不再单独发送 identity |
| `system_layout`  | `identity`        | billing 与官方 identity 分成两个 block                 |
| `timezone`       | egress profile 提供 | IANA 时区，例如 `America/New_York`                   |
| `caller_system`  | `append`          | 原样保留调用方 system block                            |
| `execution_mode` | `native_slot`     | CLI 内部槽位控制，不让模型执行 `slot_wait/kin_done`          |
| `stream_source`  | `cli`             | Claude CLI 原生 `stream_event` 是唯一正文源             |


### zero 模式

```json
{
  "system": [
    {
      "type": "text",
      "text": "x-anthropic-billing-header: <CLI生成字段>; prompt_version=You are a Claude agent, built on Anthropic's Claude Agent SDK.;"
    },
    {
      "type": "text",
      "text": "# Environment\nTime zone: America/New_York"
    },
    {
      "type": "text",
      "text": "<调用方 system，存在时追加>"
    }
  ]
}
```

### identity 模式

```json
{
  "system": [
    {
      "type": "text",
      "text": "x-anthropic-billing-header: <CLI生成字段>;"
    },
    {
      "type": "text",
      "text": "You are a Claude agent, built on Anthropic's Claude Agent SDK."
    },
    {
      "type": "text",
      "text": "# Environment\nTime zone: America/New_York"
    },
    {
      "type": "text",
      "text": "<调用方 system，存在时追加>"
    }
  ]

```

`cc_version`、构建指纹、`cch`、`cc_prompt_id` 不应由控制台手工填写，必须由实际 CLI 构建和运行时产生。当前源码明确表明 `cch` 是 Bun 原生 HTTP attestation 功能；Node 构建没有这项能力时应省略，不能填伪造值。

## Claude CLI 补丁边界

需要修改四部分。

1. System 布局

在 system.ts 和 claude.ts 增加：

```text
CLAUDE_CODE_SYSTEM_LAYOUT=zero|identity
CLAUDE_CODE_TIMEZONE=America/New_York
```

由 CLI 决定 billing/identity block 的布局，Rust 不构造这些内容。

2. 删除子代理默认增强

目前 AgentTool.tsx 和 runAgent.ts 会自动追加：

- cwd/git/platform/shell/OS
- 模型名称与知识截止日期
- 文件路径和报告规则
- 其他 Claude Code 子代理说明

`native_slot` 模式必须跳过 `enhanceSystemPromptWithEnvDetails()`，只保留最小 Environment 时区块。

3. 把槽位生命周期移出模型

理想结构不是让模型调用：

```text
slot_wait → 回答 → kin_done → slot_wait
```

而是 CLI 内部新增 `NativeSlotRunner`：

```text
等待 Rust job
→ 创建/恢复 QueryEngine
→ 使用调用方 system/messages/tools
→ 向 Anthropic 请求
→ 原样输出 StreamEvent
→ 遇到客户端 tool_use 时暂停
→ 收到 tool_result 后恢复
→ end_turn 后槽位重新等待
```

这样 API transcript 里不再出现：

- `mcp__kin_runtime__slot_wait`
- `mcp__kin_runtime__kin_done`
- Kin 控制提示
- job JSON 包装提示

这才是“子代理行为和主 agent 一致”。

4. 原生 stdout 协议

建议补丁输出明确关联帧，不再依赖推测 `parent_tool_use_id`：

```json
{
  "type": "kin_stream_event",
  "job_id": "job-...",
  "slot_id": "slot-03",
  "event": {
    "type": "content_block_delta",
    "delta": {
      "type": "text_delta",
      "text": "..."
    }
  }
}
```

CLI 必须在收到 Anthropic 每个 SSE event 后立即写 stdout，不能等待完整 assistant message。

## SOCKS5 与时区

SOCKS5 地址本身无法推导可靠时区。控制台应把它们作为同一个原子配置管理：

```json
{
  "egress_profile": "iad-01",
  "socks5_secret_ref": "proxy/iad-01",
  "timezone": "America/New_York"
}
```

启动 CLI 前同时设置：

```text
TZ=America/New_York
CLAUDE_CODE_TIMEZONE=America/New_York
```

必须使用 IANA 时区，不能只配 `UTC-4`，否则夏令时会错误。由于 Node/Intl 会缓存进程时区，切换 SOCKS 或时区时应先 drain 20 个槽，再重启单个 CLI PID。

## 网络路径

当前 Messages Relay 由 Rust 发起上游 TLS，不属于 CLI 原装网络路径。新模式应关闭它：

```text
KIN_RELAY_MODE=off
ANTHROPIC_BASE_URL 不设置
```

推荐在 Rust 内核中提供一个只支持 `CONNECT` 的本地 SOCKS 隧道：

```text
Claude CLI
→ localhost HTTP CONNECT
→ SOCKS5
→ api.anthropic.com
```

该隧道不解密、不修改 HTTP/SSE；TLS 和 Anthropic SDK 请求仍由 Node CLI 产生。相比在 Claude Code 中引入新的 SOCKS HTTP agent，这个方案补丁更小，也更接近原装传输行为。

## Rust 内核调整

当前 [supervisor.rs](http://supervisor.rs) 和 mcp_[server.rs](http://server.rs) 仍要求正文进入 `kin_done.text`，这条路径应废弃。

Rust 新职责：

- stdin 发送 `job_start/tool_result/cancel`。
- stdout 按 `job_id` 直接 demux。
- Anthropic入口：基本原样输出。
- OpenAI/Gemini入口：逐事件转换。
- `stream:false`：由 Rust 聚合。
- CLI 原生 delta 是唯一正文权威源。
- 聚合 assistant 帧仅用于校验，不能重复发送。
- 有界队列和慢客户端显式失败逻辑继续保留。

## Go 控制台

不要开放任意环境变量注入，采用白名单配置：

```json
{
  "execution_mode": "native_slot",
  "system_layout": "zero",
  "timezone": "America/New_York",
  "egress_profile": "iad-01",
  "caller_system_policy": "append",
  "stream_source": "cli"
}
```

变更流程：

```text
保存配置
→ 校验 IANA timezone/egress profile
→ 生成 config hash
→ 内核停止接新任务
→ 等待现有槽完成
→ 重启一个 CLI PID
→ healthz 返回 applied hash/capabilities
→ 恢复调度
```

## 实施顺序

1. 先实现 `zero/identity` system 布局和最小时区 Environment。
2. 修改现有 prompt：正文正常输出，`kin_done` 只带元数据，先验证原生 `text_delta`。
3. 新增 `native_slot` CLI 宿主循环，彻底移除模型可见的 `slot_wait/kin_done`。
4. Rust 切换为 CLI stdout authoritative，Relay 仅保留兼容回滚。
5. 加入 CONNECT→SOCKS 隧道和 Go egress profile。
6. 验收 1、5、20 并发，以及 tool_result continuation。

最终验收标准是：抓包中没有 Claude Code 默认长 prompt、没有 Kin MCP 控制 transcript；Anthropic SSE 的每个 `text_delta` 都能按顺序出现在 CLI stdout 和用户 SSE 中；20 并发维持单 CLI PID，整机 RSS 控制在 2–4 GB。
